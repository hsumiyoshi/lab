# 収集基盤（宣言＋パーサ）

**新しい収集を追加する手順は2つだけ**:
1. `sources.py` にパーサ関数を1つ書く（`text -> list[dict]`）
2. 同じファイルの `SOURCES` に宣言を30行足す

これだけで、以下が**自動で**付いてきます:

| ガード | 中身 | 由来した事故 |
|---|---|---|
| 礼儀つき取得 | ホスト別のレート制限・指数バックオフ・429はRetry-After尊重・keep-alive・gzip | Open-Meteoの429で提出ジョブ停止（8/21-22） |
| IPv4強制（任意） | `fetch: {ipv4: true}` | NASAへIPv6で到達できずCI失敗（8/23） |
| 生情報の保存 | `raw: {save: true}` で構造化した中身を日付つき保存 | 抽出後の1数値しか残さず、後から問い直せなかった（8/24） |
| 重複排除・追記 | keyで冪等に台帳へ追記 | — |
| **件数とスキーマの検査** | `expect: {rows: [lo,hi], schema: [...]}` を外れたら**失敗させる** | パーサ破損で0件でも「成功」になる沈黙（#18の系統） |
| 障害ログ | `docs/incidents.md` へ自動追記 | 手で埋めて真因が4日隠れた（8/19） |
| 原子的書き込み | tmpへ書いてreplace | 途中で落ちた時に壊れたファイルを残さない |

## 作らないもの（意図的な線引き）

汎用ETL・スケジューラ・ワークフローエンジン・UI・DB。**GitHub Actionsとgitで足りている部分は置き換えない**。この骨格の目的は「同じ穴が二度と開かないこと」であって、基盤を持つこと自体ではない。

## 移行の状況（2026-08-24・全面移行）

**方針（Haruki）**: 「基盤構築だから多少保守が重くなっても、そっちに寄せる安心感を得たい」——
1ソースのためでも抽象を足し、**例外を作らない**方向で統一した。

| 対象 | 方式 | 備考 |
|---|---|---|
| 出力制御・書籍 | **宣言＋パーサ**（sources.py） | ガードが全部付く完全形 |
| JEPXスポットCSV | ランタイム経由（**bytes版**） | cp932の往復デコードで中身が変わる事故を実測→bytes版を追加 |
| 気象（Open-Meteo 8地点） | ランタイム経由 | 429のRetry-After尊重を共通化 |
| 地震（P2P API） | ランタイム経由 | |
| 気象庁JSON・GDACS RSS | ランタイム経由 | |
| FIRMS | ランタイム経由（**ipv4: true**） | IPv4強制をランタイムの機能へ昇格 |
| **青果（ベジ探）** | ランタイム経由（**POST**） | この1本のためにランタイムへPOSTを追加 |
| **衛星のSTAC検索** | ランタイム経由（POST JSON） | |
| 衛星のCOG読み出し | **設定で統一** | rasterio(GDAL)が内部でHTTPレンジ取得するため経路は寄せず、リトライ・待機・タイムアウト・不要なHEAD抑制をGDAL環境変数で同じ思想に揃えた |

**残る例外はゼロ**（COGは経路でなく設定で統一）。

## 実行

```bash
python3 collector/collect.py            # 全ソース
python3 collector/collect.py tohan_books   # 個別
```
