## 意地悪な注文書50行での精度（2026-10-13）

計画: 「意地悪な注文書で精度を測る: 手書き風・かすれ・略記・FAXの傾き入りを50行作り、正解率と『確認に回った行』の割合を出す」

### 結論
1. **読み取りが完璧でも、自信を持って誤る行が50行中3行ある。3行とも「同名で規格違い」**。規格を書かない「業務用タオル」「ゴミ袋」「おいしい生パン粉L60」を、候補が2つ同点で並ぶのに品番の大きい方に決めた。同名の判定は「括弧を除いた品名が一致」のときだけ働き、大/小・45L/10L・DL/M のように品名の本文で規格が違う品は素通りする
2. **Tesseractでは、罫線を拾えない用紙で表の中身が丸ごと消える**。読み落としは活字・手書き風とも50行中12行で、消えた行は要確認にも出ない（確認画面の行が減るだけ）
3. **数量と納期は要確認の判定に入っていないので、読み違いが黙って通る**。「20袋」→2088、「10袋」→1088、取消線の「~~5~~6」→56。品番は正しく自動確定したのに数量か納期が違う行が、活字・手書き風とも3行ある

### 作り方
- 50行・20枚。商品一覧4つ（架空15行・富士パン粉12・オーサワ12・マイン11）× 難しさ5種（各10行）。正解は `hard/truth.csv`（品番・数量・納期・期待＝確定か要確認）
- 用紙は罫線つき10行の欄を先に印刷し、上から埋める（欄が2〜3行だけだと、罫線検出の長さの条件に届かず落ちる。試験の作りの都合で落とさないため）
- **手書き風**: 元の環境に手書き風の日本語フォントは無かった。apt の `fonts-klee`（Klee One・硬筆調のフォント）を入れ、1字ずつ傾き・大きさ・位置を揺らした。**本物の手書きではない**（同じ字は同じ形になる）

| 難しさ | 中身 |
|---|---|
| 略記 | 規格・ブランド名を落とす、半角カナ、ひらがな（くるとん）、括弧の中の別名だけ（亜麻仁油）、全角数字、c/s |
| 誤字・書き損じ | 1字違い・脱字（粉→紛、ー→一、ス→ズ、ッ抜け）、取消線で書き直し（品名2行・数量2行） |
| 同名で規格違い | 規格を書かない8行（期待＝要確認）と、規格を書いて1点に決まる2行（期待＝確定） |
| かすれ・ノイズ | 濃淡むら・黒点の欠け・解像度落ち（横0.6・縦0.45倍）・ごま塩0.8%・縦すじ1本。既定はぼかし0.6とごま塩0.2%だけ |
| 傾き・ずれ | 用紙の傾き 2.0／-2.8／3.5／-4.5度、字が罫線にかかる（上・下・左）、数量が納期の列にはみ出す |

略記・誤字・同名の用紙は make_fax.py と同じ既定の崩し（傾き±0.8度・ぼかし・ごま塩0.2%・2値）。

### 条件と数え方
- **A_print**: 記入欄も活字の画像 → Tesseract
- **A_hand**: 記入欄が手書き風の画像 → Tesseract（傾き・ノイズは A_print と同じ）
- **B**: 完全な読み手。シートの字そのまま（略記・誤字は残し、取消線の字は除く）を `--lines` と同じ形で渡す。品番への変換と要確認の判定だけを測る
- 自動確定＝確度0.9以上（確認画面の「一致」）。**自信を持って誤った行**＝自動確定のうち、品番が違う行と、期待＝要確認なのに決めた行。読み落とし＝確認画面に出てこない正解行。数量・納期は確認画面に出た行のうちの正解数

### 品番は正しく自動確定したが、数量か納期が違う行
- A_print: H31 納期「10/15」が空、H40 数量10→2・納期「来週」が空（割れた品名の残り「ピロー袋入」を「2ロ一義入」と読み、その2を数量に取った）、H46 納期「10/16」→「10716」で空
- A_hand: H02 数量「3ｹｰｽ」→39・納期「至急」が空、H36 数量「8袋」→1・納期が空、H45 納期「来週」が空

### 読み落とし12行の内訳
| 原因 | A_print | A_hand |
|---|---|---|
| 罫線を拾えず、表の中身ごと消えた（傾き3.5・-4.5度の2枚。傾き補正は3度未満まで。±0.8度内でも補正後に0.1度強残った S_ohsawa（活字のみ）・S_mine） | 9 | 7 |
| 罫線の一部がかすれて消え、2行が1つのマスになって品名が読めず捨てた（N_fict） | 2 | 2 |
| 数量のマスに数字が読めず、注文行と見なされずに捨てた | 1 | 3 |

罫線を拾えない用紙はページ全体を行で読む（`_ocr(image, 6)`）が、表の中は読まれなかった。代わりに見出しの行（株式会社サンプル商店御中発注日2026/10/13）が、数量20や382520の注文行として出た（確度0.1前後なので要確認）。

### そのほか
- B の要確認22行のうち20行は、候補3つに正解がある。無いのは H05「くるとん」（ひらがな。カタカナと同一視しない）と H30「大人用パイル地スリッパ 黒」（候補3つは子供用2点と黒40セット。同じ品名の黒160セットは、同点の黒40セットに枠を取られた）。確認画面の選択肢は候補3つと「該当なし」だけなので、この2行は画面上で正解を選べない
- B で規格を書いた2行（なたねサラダ油 600g・歯ブラシ PBT-00-SPP 350本入）も要確認に回る。照合が品名の列だけを見て、規格の列を使っていない
- B で納期を読めなかった2行は「10月20日」「明日」。納期の書式は `10/20`・至急・来週・今週・月末だけ
- Tesseract が `"` で始まる語を返すと、`_ocr()` の TSV 読み込み（csv の既定の引用符処理）が後続の行を1つの欄に飲み込む（A_hand の K_mine・N_mine で発生）
- 試験は仕組みの中身を知っている者（Claude）が作った。意地悪の向きが仕組みの弱点に寄っている可能性がある

### 結果が指す直し
1. **同名判定を広げる**: 上位2つが同点なら、括弧の有無に関係なく要確認にする。規格の列（g・入数）も照合に使い、「600g」「350本入」と書かれていれば決める
2. **罫線を拾えない・行数が合わない用紙は、用紙ごと要確認にする**: 黙って行が減るのを止める。あわせて傾き補正の範囲（3度未満）と角度の刻み（0.25度）を見直す
3. **数量・納期を確認の対象に入れる**: 桁が多すぎる数量、単位が化けた数量、取消線のあるマス、読めない納期は要確認にする。納期の書式（月日・明日）を足す

再現: `python3 hard/make_hard.py hard/truth.csv hard/img/print --style print`（`--style hand` は `fonts-klee` が要る）→ `python3 hard/run_hard.py`（3条件で約5分）。`run_hard.py` は pipeline.main() と同じ順で pipeline の関数を呼び、行の位置を残して正解と対応させる。make_fax.py は `fit()` にフォントを渡せるようにしただけ（既定は従来どおり）。
