### 仕組みの決まり
**自信を持って誤らない。行を黙って落とさない。** 確かでない行は「要確認」に回し、事務員が誤った品番をそのまま書き出せないようにする。

| 場面 | 決まり |
|---|---|
| 品番 | 書かれた品名を含む品が2つ以上（大/小・45L/10L・入数違いの同名・括弧の付記だけ違う品）なら決めない。規格の字（g・mL・L・入数・サイズ）が書かれていて1つに絞れたときだけ決める。品番の大小や一覧の並び順で同点を決めない |
| 数量 | 3桁以上・単位の字が化けた（「3ケ-」「$6」）・数字が2つある・読み取り確度80未満は要確認。画像から読んだ行で品名が一覧と合わない（不明）なら、数量・納期にも印を付ける |
| 納期 | 「10/20」「10月20日」「10/20(火)」「明日」「明後日」「本日」「月末」「来週」「今週」「至急」を読む。日付になるものは受信日（`--date`）から年月日（ISO）も出す。「至急」は印として残す。読めない・受信日より前は要確認 |
| 用紙 | 罫線を拾えない・2行分の高さのマスがある・下の横線が無い用紙は「用紙ごと要確認」。確認画面の上に理由を出し、用紙の確認に印を付けるまで書き出させない |
| 行 | 品名のマスに字の跡があれば、数量が読めなくても行を残す（数量を空にして要確認） |
| `--lines` | 読み取り済みの字だけの入力として扱う（読み取りの確度は使わない。品番の判定と数量・納期の検査だけで決める） |

確認画面（`review.html`）
- 品番の選択肢は「品番 品名 規格」（例「OJ-013 オーサワのなたねサラダ油 1360g」）。要確認・不明の行は「選んでください」（空）で始め、候補を押せる形で並べる。品名が1つに決まったが数量・納期が怪しい行も品番は空で始め、決まった品番を候補の先頭に置く
- 行ごとに「一覧から探す」（品名・規格・品番で商品一覧全体を探す。ひらがな・カタカナを区別しない）
- 品名・数量・単位・納期を直せる。行の追加（読み落とし・電話の注文）と削除ができる
- 選ぶ・直すと判定のバッジと「n行が要確認」がその場で変わる。未確認の行が残るあいだはCSVを書き出させず、残りの行番号を出す

`check_review.py` で3社の確認画面と、用紙ごと要確認になる試験用紙（`hard/img/print/N_fict.png`）の画面を操作して確かめた。4画面とも全項目が通った（各15〜16項目）。確かめたこと: 要確認・不明の行が空で始まる／未確認が残るあいだは書き出せず行番号が出る／候補に無い品を一覧全体から探して選べる（富士パン粉では FP-011 が候補に無い6行目で「白生」→ FP-011 白生（蕨）、オーサワ2行目で「なたね 600」→ OJ-014、マイン1行目で「スリッパ 黒 160」→ MN-027。探す仕組みの確かめで、その行の正解とは限らない）／選ぶとバッジと数が変わる／行の追加・削除／「10月20日」を 2026-10-20 にする／用紙の確認に印を付けるまで書き出せない。富士パン粉1行目は、今の読み取りが「白生(藤)」と読むので FP-011 は候補の先頭に入っている（「白生」で探しても出る）。

画像を読むAIに替えた場合（`pipeline.py --lines` に読み取り済みの行を渡す。APIキーが未設定のため、`out/mine/ai_read.txt` の8行はTesseractではなく、Claudeが画像を見て書き起こした）: 8/8行を読み、品番が1つに決まったのは2行（ネックピロー・歯ブラシ PBT-25。どちらも正解）。残る6行は、同じ品名で入数だけ違う品が2つずつ並ぶ（例: スリッパ160セットと40セット）。FAXに入数が書かれていないので品番を空のまま要確認に回し、6行とも候補の先頭2つに正解がある。同点の2つから品番の大きい方を選べば7/8が当たって見えるが、それは並び順の偶然で、入数を決めるのは人か得意先ごとの「いつもの」辞書。前後の絵は out/mine/before_after.png
読み取り部は画像を読むAI（API）に差し替えられる形（`read_sheet()` を替える）。自分の仕組みは、辞書・確認画面・CSV・前後の絵。

## 意地悪な注文書50行での精度（2026-10-13）

計画: 「意地悪な注文書で精度を測る: 手書き風・かすれ・略記・FAXの傾き入りを50行作り、正解率と『確認に回った行』の割合を出す」

### 結論
1. **自信を持って誤った行は3条件とも0、黙って消えた行も0になった。** 成功の基準（自信を持って誤った＝0、表に出ない読み落とし＝0）を3条件とも満たす
2. **代わりに、Tesseractでは確認に回る行が増えた。** 活字は50行中43行、手書き風は49行が要確認（前は27行・34行。前の値には黙って消えた12行が入っていない）。自動確定は活字7行・手書き風1行で、すべて正解。手書き風は、品名がほぼ読めないので仕組みとしては「全部人が見る」と同じ。読み取り部を画像を読むAIに替えるまで、自動化の幅は出ない
3. **完全な読み手（B）では、自動確定29行がすべて正解、要確認21行はすべて候補に正解がある。** 同名で規格違いの8行は品番を空のまま要確認、規格を書いた2行（なたねサラダ油 600g・歯ブラシ 350本入）は規格の列で1つに絞って確定する

### 作り方
- 50行・20枚。商品一覧4つ（架空15行・富士パン粉12・オーサワ12・マイン11）× 難しさ5種（各10行）。正解は `hard/truth.csv`（品番・数量・納期・期待＝確定か要確認）
- 用紙は罫線つき10行の欄を先に印刷し、上から埋める（欄が2〜3行だけだと、罫線検出の長さの条件に届かず落ちる。試験の作りの都合で落とさないため）
- **手書き風**: 元の環境に手書き風の日本語フォントは無かった。apt の `fonts-klee`（Klee One・硬筆調のフォント）を入れ、1字ずつ傾き・大きさ・位置を揺らした。**本物の手書きではない**（同じ字は同じ形になる）

| 難しさ | 中身 |
|---|---|
| 略記 | 規格・ブランド名を落とす、半角カナ、ひらがな（くるとん）、括弧の中の別名だけ（亜麻仁油）、全角数字、c/s |
| 誤字・書き損じ | 1字違い・脱字（粉→紛、ー→一、ス→ズ、ッ抜け）、取消線で書き直し（品名2行・数量2行） |
| 同名で規格違い | 規格を書かない8行（期待＝要確認）と、規格を書いて1点に決まる2行（期待＝確定） |
| かすれ・ノイズ | 濃淡むら・黒点の欠け・解像度落ち（横0.6・縦0.45倍）・ごま塩0.8%・縦すじ1本。既定はぼかし0.6とごま塩0.2%だけ |
| 傾き・ずれ | 用紙の傾き 2.0／-2.8／3.5／-4.5度、字が罫線にかかる（上・下・左）、数量が納期の列にはみ出す |

略記・誤字・同名の用紙は make_fax.py と同じ既定の崩し（傾き±0.8度・ぼかし・ごま塩0.2%・2値）。

### 条件と数え方
- **A_print**: 記入欄も活字の画像 → Tesseract
- **A_hand**: 記入欄が手書き風の画像 → Tesseract（傾き・ノイズは A_print と同じ）
- **B**: 完全な読み手。シートの字そのまま（略記・誤字は残し、取消線の字は除く）を `--lines` と同じ形（字だけ・確度なし）で渡す。品番への変換と要確認の判定だけを測る
- 自動確定＝判定が「一致」（確認画面でそのまま書き出せる行）。要確認＝「要確認」と「不明」
- **自信を持って誤った行**＝品番が入った状態で出た行のうち、品番が違う行と、期待＝要確認なのに決めた行。品番が入った状態で出るのは「一致」の行だけ
- 読み落とし＝確認画面に出てこない正解行。用紙ごと要確認の用紙なら「表に出た」、そうでなければ「黙って消えた」
- 一致なのに数量か納期が違う＝「一致」の行で数量か納期が正解と違う行。数量か納期の誤りに印なし＝確認画面に出た行で、数量か納期が違うのにそのマスに要確認の印が無い行（品番だけを直して通すと誤りが残る）
- 数量・納期は確認画面に出た行のうちの正解数

- 実在の注文書・取引先名・個人情報は使わない。商品名は公開サイトの一覧のみ。架空の数量と架空の得意先名
- 前後の絵には「架空」と明記する
