# exp13 FAX注文のデータ化（試作・2026-10-05）

本線（卸・メーカー向け）の仕組みの試作。**相手に何も頼まず、公開の商品一覧で先に動かした結果を添付して届ける**ために作った。

| ファイル | 役割 |
|---|---|
| `make_fax.py` | 架空のFAX注文書を描く（商品一覧CSVから。略した品名・傾き・ノイズ・2値化） |
| `pipeline.py` | 読み取り（Tesseract jpn+eng。傾き補正→罫線でマスに切って1マスずつ）→ 品番への変換（辞書＋あいまい一致。同名で規格違いは人に選ばせる）→ 確認画面（review.html。直してCSVを書き出す） |
| `compose.py` | 「前後」の1枚絵（左: FAX、右: 確認画面のスクリーンショット） |
| `sample/catalog*.csv` | 架空の商品一覧（30点）と、公開サイトから取った商品名（富士パン粉工業31点・オーサワジャパン16点・マイン34点。品番は仮） |

結果（架空の注文書8行）: 架空30点で 読み取り8/8・自動で品番が当たる6・要確認2、富士パン粉で 8/8・7・1、オーサワで 8/8・4・4。3つとも「自信を持って誤る」行は0（同名で規格違い、括弧の付記だけ違う品名は人に選ばせる）。長い品名は、人が書くように字を小さくするか2行に折ってマスに収める。

マイン（mine-shop.jp の公開34点。型番入りで、歯磨き粉のg数・袋か箱・入数だけ違う品が並ぶ）では、Tesseractの読み取りが崩れた。8行中、使える品名が読めたのは3行（歯ブラシ2・マウスウォッシュ1）で、2行に折った長い品名（スリッパの寸法表記・アメニティセット）は崩れるか落ちた。確認不要と出して誤った行は0。**この型の相手は、読み取り部を画像を読むAIに替えないと前後の絵にならない**。
画像を読むAIに替えた場合（`pipeline.py --lines` に読み取り済みの行を渡す。APIキーが未設定のため、今回はClaudeが画像を見て書き起こした行を使った）: 8/8行を読み、候補1位の品番は7/8で正解。要確認の6行はすべて「同じ品名で入数だけ違う」（例: スリッパ160セットと40セット）で、FAXに入数が書かれていない以上、人か得意先ごとの「いつもの」辞書が決めるべき行。前後の絵は out/mine/before_after.png
読み取り部は画像を読むAI（API）に差し替えられる形。自分の仕組みは、辞書・確認画面・CSV・前後の絵。

## 守ること
- 実在の注文書・取引先名・個人情報は使わない。商品名は公開サイトの一覧のみ。架空の数量と架空の得意先名
- 前後の絵には「架空」と明記する
