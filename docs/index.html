公証の仕組み

  1. picksは市場価格の公表前にコミットされる——後出しは不可能
  2. gitのコミット履歴が、改竄不能なタイムスタンプ＝公証になる
  3. 負けた記録も削除しない。全履歴が誰でも検証できる

この実験場について

個人が一人で運用しています。副業として、平日の数時間と休日だけを使って、 50年必要とされる領域で事業を作れるかを確かめるための実験場です。 予測を当てること自体が目的ではなく、当たったか外れたかを人に見える形で残し続ける運用が 成立するかを試しています。だから負けもそのまま置いてあります。

技術的な手足はほぼAIに任せていて、この台帳もダッシュボードも 毎日CIが自動生成しています。人が触るのは設計と判断だけです。

GitHub @hsumiyoshi English 質問・指摘はIssuesへ

In English

I run 10 prediction leagues against real-world data. Every prediction is committed to git before the outcome exists, so the goalposts cannot move afterwards — and the losses stay in the ledger.

Each league has three things: a dumb baseline it must beat, an oracle (the best possible result in hindsight) to measure against, and a scoring date fixed in advance. The scoreboard at the top of this page shows where each league stands, including the ones currently losing to their baseline.

Why git? A commit timestamp is a notary that costs nothing. Day-ahead electricity prices are published at 10:00 JST; the picks are committed at 07:00 JST. Anyone can check the history and verify the order of events. This page is regenerated from the ledgers by CI every day — no hand edits.

Charts are rendered in English because the CI runners have no Japanese font; the Japanese captions below each chart explain how to read them.

何の勝負？

仮想蓄電池のデイリー売買ゲーム

毎日、翌日48コマ（30分刻み）の価格を予測。安い4コマで充電（買）、高い4コマで放電（売）。差額が損益になり、答え合わせは翌日13:30。

答えを見て動いた場合の理論上限（参照値。順位には入らない）

並びは対oracle順＝答えを見た理論上限に対する到達率。価格公表前にコミットされた日だけで計算する。clockは予測を一切しない脳死ベンチ、oracleは答えを見た上限で、どちらも順位には入らない。事前でない日＝公表前にコミットされていない日で、内訳はBT補完（参戦前の穴埋め）と再計算（提出が無く採点時にコードから作った日）。この列が100%の機体は実力のレートが未計測なので「参考」の値を薄く出す

縦軸は上限の何%を取れたか。灰色の帯は予測を一切しなくても届く領域——clockは毎日同じ時間に売買するだけだが、電力価格の日内周期のせいで上限の8割強に達する。つまり勝負はこの帯の上、残り2割弱の奪い合いで起きている。90%台という数字を実力と読まないための線。立ち上がりは分母が小さく比率が暴れるため、各機体4日目から描く。clockとweekshapeにまだ線が無いのは、提出型への切り替えが2026-08-27だから——それ以前は再計算＝事前コミットではないので描かない。基準線だけは全日ベースで引いている（clockは引数を取らない固定ルールなので再計算しても値が動かない）
